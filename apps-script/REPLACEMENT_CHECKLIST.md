# Apps Script 대체형 검증표

목표: 담임교사가 설치형 없이 Apps Script 웹앱에서 하루 일과를 운영하고, 학생이 Chromebook·Android 탭에서 같은 학급 데이터를 확인·응답한다. Windows 작업표시줄 알림은 범위에서 제외하고 열린 페이지 안의 대형 팝업과 효과음으로 대체한다.

## 코드로 구현한 범위

- 개인 Gmail 소유자, 교사·학생 이메일 인증과 역할별 서버 권한
- 주차별 시간표, 학교급별 기본 수업 길이, 중간놀이·점심·5·6교시 하교, 과목 기본 메시지·링크
- 학사관리 XLSX의 날짜·과목을 브라우저에서 직접 해석해 해당 주 시간표로 가져오기
- 개별 일정 추가·수정·삭제와 시작·사전 알림 대형 팝업, 3회 반복 효과음
- 공통 쉬는 시간·중간놀이·점심 안내, 단일 알림음·음량, 교사·학생 공용 타이머
- 수동 종료 기록과 시간 기준 자동 종료 표시, 다음 수업 학생·교사 전달 메모
- 이메일 명렬·성별·알레르기, 급식·날씨, 1인 1역 중 그날의 크린토피아·우유
- 나이스 학교 이름 검색 후 교육청·학교 코드 선택
- 자리 배치 생성·교환·확정 이력, 설치형 백업에서 항목별 선택 가져오기
- 1인 1역 전체 역할·학생 배정 편집과 A4 한 페이지 인쇄
- 온라인 학급 데이터 전체 JSON 백업과 날짜별 종료 기록 CSV 내려받기
- 학생 준비·이해도·질문·도움 요청·마무리 응답, 교사 집계

## 아직 설치형을 없애면 안 되는 이유

- 실제 Google 시험 배포에서 새 시트 생성·기록·권한을 끝까지 검증하지 않았다.
- 실제 교사·학생 계정, Chromebook·Android 탭에서 팝업/효과음/절전 동작을 확인하지 않았다.
- 24명 동시 접속의 Apps Script 호출량과 지연을 측정하지 않았다. 현재 담임 5초·학생 12초 폴링은 부하 시험 뒤 조정해야 한다.
- 설치형 전체 백업의 16주 초과 시간표, 200건 초과 기록·전달 메모를 분할 가져오는 경로가 없다.
- 온라인 전체 JSON 백업은 만들었지만, 설치형 복원 호환성과 대량 데이터 왕복을 실제 파일로 검증하지 않았다.
- 학사관리 XLSX 가져오기는 코드와 설치형 파서 동일성만 검증했다. 실제 Apps Script 웹앱에서 샘플 파일로 저장까지 확인해야 한다. 자리 배치 대형 인쇄/CSV 내려받기는 아직 없다.
- 개별 생성 수업 시간의 예외 수정은 설치형만큼 세밀하지 않다. 온라인판은 주간 공통 구조와 별도 일정 편집을 제공한다.
- 사용자 사용 중지·졸업·학급 이동과 기록 보존/삭제 정책을 운영자 화면에서 아직 완결하지 않았다.

## 안전한 적용 순서

1. 설치형 데이터를 `전체 백업` JSON으로 보관하고, 학생 이메일을 확인한다. 2026-09-04 백업은 학생 24명의 이메일이 모두 비어 있어 로그인·자리 배치 이전용으로는 부족하다.
2. `clasp push`로 시험 `@HEAD` 소스에만 반영한다. 버전 6 일반 배포는 그대로 둔다.
3. 마스터 계정으로 시험 웹앱을 열어 새 시트와 교사 화면을 확인한다. 실제 학생 데이터 대신 시험 학급·시험 명렬로 먼저 수행한다.
4. 시간표/개별 일정 → 사전·정시 팝업 → 종료 기록/전달 메모 → 자리 배치 → 학생 응답을 차례로 검증한다.
5. 실제 백업은 항목을 나눠 가져오고, 이력 덮어쓰기 전 별도 사본을 보관한다.
6. 교사·학생 기기와 부하 시험을 통과한 뒤 새 버전 배포 주소를 전환한다. 그 전에는 설치형을 유지한다.

## 개인정보 경계

- Apps Script 소유자의 원본 스프레드시트를 학생에게 공유하지 않는다.
- 학생 응답에는 다른 학생의 이메일·성별·알레르기·교사 전용 메모·자리 이력을 포함하지 않는다.
- 백업 가져오기는 체크한 항목만 브라우저에서 서버로 보낸다. 알레르기·기록·전달 메모·자리 이력은 별도 선택 항목이다.
- 급식·날씨 API에는 학생 이름과 알레르기 명렬을 보내지 않는다.
