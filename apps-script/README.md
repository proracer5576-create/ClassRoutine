# 오늘도, 차근차근 · Apps Script 온라인 교실

기존 Windows 설치형의 일정 알림을 대체하는 프로젝트가 아니라, 학교 Google Workspace SSO와 학생 응답 수집을 담당하는 온라인 교실 모듈이다.

## 현재 구현 범위

- Google Workspace 로그인 이메일을 서버에서 확인
- 마스터·담임교사·학생 역할별 화면과 서버 권한 검사
- 마스터의 학급·담임 이메일 연결
- 담임의 학생 이메일 명렬 일괄 등록
- 수업 제목·공개 안내·학습 링크·빠른 질문 게시
- 학생의 준비 완료·이해도·빠른 질문·도움 요청·한 줄 마무리 제출
- 담임 화면의 응답 수·이해도·질문 결과·도움 대기열 집계
- Google Sheets 영구 저장과 `LockService` 동시 기록 보호
- 사용자 입력의 길이 제한, 수식 주입 방지, `https://` 링크만 허용
- 나이스 오늘 급식과 기상청 단기예보 연동
- 학생별 알레르기 번호 대조와 본인 전용 주의 음식 표시
- 날씨 기반 실외활동 참고 안내

## 파일

- `Code.gs`: SSO 판별, 역할 권한, Sheets 저장, 교사·학생 API
- `Index.html`: 역할별 화면 구조
- `Styles.html`: 반응형 교실 UI
- `Client.html`: `google.script.run` 통신, 렌더링, 카운트다운과 폴링
- `appsscript.json`: 최소 OAuth 범위와 서울 시간대

## 최초 설치

1. 학교 Workspace 계정으로 독립형 Apps Script 프로젝트를 만든다.
2. 이 폴더의 파일을 프로젝트에 동일한 이름으로 추가한다. `appsscript.json`은 프로젝트 설정에서 매니페스트 표시를 켠 뒤 적용한다.
3. Apps Script 편집기의 함수 목록에서 `setupDatabase`를 선택해 한 번 실행하고 권한을 승인한다.
4. 생성된 Google Sheets 파일을 확인한다. 학생에게 이 원본 Sheet를 공유하지 않는다.
5. `배포 → 새 배포 → 웹 앱`을 선택한다.
6. 실행 사용자는 배포 소유자, 접근 사용자는 학교 조직 사용자로 제한한다.
7. 배포 주소를 학교 계정으로 열어 마스터 화면이 표시되는지 확인한다.
8. 마스터가 학급과 담임 이메일을 등록하고, 담임이 학생 이메일 명렬을 등록한다.

## 급식·날씨 설정

마스터가 학급 카드의 `교사 화면 열기`를 누르거나 담임이 로그인한 뒤 `급식·날씨 연결`에서 설정한다.

- 나이스: 교육청 코드, 학교 코드, 나이스 교육정보 개방 포털 인증키
- 기상청: 동네예보 격자 X·Y와 공공데이터포털 인증키
- 학생 명렬: `이메일, 번호, 이름, 알레르기번호` 순서이며 여러 번호는 `1|2|6`처럼 입력

알레르기 번호는 나이스 급식 표기의 1~19번을 사용한다. 학생 이름과 알레르기 정보는 나이스·기상청 API로 보내지 않으며, 가져온 식단과의 대조는 Apps Script 서버 내부에서 수행한다. 자동 결과는 참고용이므로 실제 배식 전 학교 식단표, 제품 표시와 학생별 관리 지침을 다시 확인해야 한다.

함수 목록에는 `setupDatabase`가 표시된다. 이 공개 진입점은 현재 접속 계정과 배포 소유자가 동일한지 확인한 후, 브라우저에서 직접 호출할 수 없는 내부 함수 `setupDatabase_`를 실행한다.

## SSO 전제와 점검

이 구현은 배포자와 사용자가 같은 Google Workspace 도메인이라는 전제를 사용한다. 서버는 매 요청마다 `Session.getActiveUser().getEmail()`을 다시 확인하며, 클라이언트가 보낸 이메일을 사용자 신원으로 사용하지 않는다.

조직 정책이나 배포 방식 때문에 이메일이 빈 값이면 앱이 접근을 거부한다. 이 경우 다음을 점검한다.

- 개인 Gmail이 아니라 학교 계정으로 접속했는가
- 웹 앱 접근 범위가 학교 조직으로 제한됐는가
- 배포자와 학생이 같은 Workspace 도메인인가
- 관리자가 Apps Script와 필요한 OAuth 접근을 허용했는가

여러 학교 도메인이나 개인 Gmail까지 지원해야 한다면 순수 Apps Script 세션 식별에 의존하지 말고 Google Identity Services의 ID 토큰을 별도 백엔드에서 검증하는 구조로 확장한다.

## 생성되는 시트

- `Users`: 이메일, 역할, 학급, 번호, 이름, 사용 상태
- `Classes`: 학교, 학급, 담임 연결
- `State`: 학급별 현재 온라인 활동
- `Responses`: 학생별 준비·이해도·질문·마무리 응답
- `HelpQueue`: 도움 요청 대기열
- `AuditLog`: 주요 변경 기록

## 개인정보 원칙

- 교사 비공개 메모를 `State`나 학생 응답에 저장하지 않는다.
- 학생에게 반환하는 데이터에는 다른 학생 이메일과 응답 내용을 포함하지 않는다.
- 담임은 자신의 학급만, 학생은 본인의 학급만 접근한다.
- 원본 Sheet는 마스터와 운영 담당자에게만 공유한다.
- 학교 개인정보 처리 기준에 따라 보존 기간과 삭제 절차를 정한다.

## 실시간 동작

학생의 버튼 응답은 즉시 저장한다. 담임 화면은 5초, 학생 화면은 12초 간격으로 상태를 갱신하고, 탭이 보이지 않을 때는 요청을 쉬게 한다. 남은 시간은 서버에서 받은 종료 시각을 기준으로 각 기기에서 매초 계산한다.

Apps Script는 WebSocket 서버가 아니므로 초 단위 전체 기기 동기화나 강제 알림 용도로 사용하지 않는다. 정확한 효과음·Windows 알림·교실 프로젝터 화면은 기존 설치형이 담당하는 하이브리드 구성을 권장한다.
