# 오늘도, 차근차근 · Apps Script 교실 루틴

개인 또는 교육용 Google 계정이 운영하는 이메일 인증형 교사·학생 웹앱이다. 목표는 Windows 설치형을 교사 화면까지 대체하는 것이다. 다만 현재는 시험 배포에서 개발 중이며, 아래의 미검증 항목이 끝나기 전에는 설치형을 지우지 않는다.

## 현재 구현 범위

- 명렬에 등록된 이메일로 6자리 인증번호를 보내 사용자 확인
- 10분 유효 인증번호, 5회 시도 제한, 12시간 브라우저 세션
- 마스터·담임교사·학생 역할별 화면과 서버 권한 검사
- 마스터의 학급·담임 이메일 연결
- 담임의 학생 명렬 저장과 이메일 계정 연결. 이메일이 없는 학생도 `RosterMembers`에 보관하고 로그인만 제한
- 명렬 등록·갱신과 전체 동기화 분리. 전체 동기화에서 제외된 학생은 로그인·기존 세션을 비활성화하고 기록은 보관
- 담임 교체 시 이전 담임 계정·인증 세션 차단, 현재 학급의 담임 이메일과 요청 계정 재검사
- 학생 성별을 별도 `StudentProfiles` 시트에 저장하고 자리 바꾸기에 사용
- 수업 제목·공개 안내·학습 링크·빠른 질문 게시
- 학생의 준비 완료·이해도·빠른 질문·도움 요청·한 줄 마무리 제출
- 담임 화면의 응답 수·이해도·질문 결과·도움 대기열 집계
- Google Sheets 영구 저장과 `LockService` 동시 기록 보호
- 사용자 입력의 길이 제한, 수식 주입 방지, `https://` 링크만 허용
- 학교명 검색으로 나이스 교육청·학교 코드를 채우고 오늘 급식과 기상청 단기예보 연동
- 학생별 알레르기 번호 대조와 본인 전용 주의 음식 표시
- 날씨 기반 실외활동 참고 안내
- 과목별 기본 학생 안내와 `https://` 학습 링크 저장
- 이번 주·다음 주 시간표 편집, 지난 저장 주 복사, 학생용 오늘 일정
- 학사관리 XLSX 시간표를 브라우저에서 직접 해석해 해당 주 시간표에 반영
- 학급 공지와 교사가 시작하는 1~10분 공용 타이머
- 교사·학생 화면의 일정 시작·사전 알림 대형 팝업, 현재 시각·카운트다운, 3회 반복 효과음
- 공통 쉬는 시간·중간놀이·점심 안내와 모든 일정에 적용되는 알림음·음량 설정
- 개별 일정 추가·수정·삭제, 수동 종료 기록과 시간 기준 자동 종료 표시, 다음 수업 학생·교사 전달 메모
- 명렬 연동 자리 바꾸기, 성별 균형·지난 짝·지난 자리 고려, 좌석 교환과 확정 회차 이력
- 설치형 전체백업 JSON에서 과목·시간표·반복 일정·공통 설정·크린토피아/우유·학생 명렬 선택 가져오기. 시간표 자동 일정은 주차별로 나눠 보관
- 종료 기록·전달 메모·자리 이력은 명시적으로 체크한 경우에만 가져오기
- 현재 온라인 학급 데이터의 전체 JSON 백업과 날짜별 종료 기록 CSV 내려받기
- 설치형 명렬과 번호·이름이 모두 일치하는 등록 학생의 알레르기 선택 갱신
- 설치형 백업을 가져오기 전 학급 범위의 비공개 복구 JSON 사본 생성, 30일 만료 정리 코드(실계정 검증 전)

학교 계정 사본의 현재 배포와 이 폴더의 수정본은 별개다. 새 코드를 사본에 반영하고 `setupDatabase`로 스키마를 보강한 뒤 새 버전으로 배포해야 한다. 교사에게 일반 Gmail, 학생에게 학교 Google 메일을 각각 등록할 수 있다. 로그인 역할은 `Users.role`과 등록 이메일 인증으로 구분하며 Google 계정 SSO 전환은 아직 구현·검증 전이다.

## 파일

- `Code.gs`: 이메일 인증, 역할 권한, Sheets 저장, 교사·학생 API
- `Recovery.gs`: 가져오기 전 학급 범위 복구 사본과 30일 만료 정리
- `Index.html`: 역할별 화면 구조
- `Styles.html`: 반응형 교실 UI
- `Client.html`: `google.script.run` 통신, 렌더링, 카운트다운과 폴링
- `TimetableImport.html`: 설치형과 동일한 XLSX 파서. 원본 파일은 서버로 보내지 않음
- `appsscript.json`: OAuth 범위와 서울 시간대. 복구 사본을 위해 `drive.file`·트리거 관리 권한 추가

## 최초 설치

1. 실제 운영할 Google 계정으로 독립형 Apps Script 프로젝트를 만든다.
2. 이 폴더의 파일을 프로젝트에 동일한 이름으로 추가한다. `appsscript.json`은 프로젝트 설정에서 매니페스트 표시를 켠 뒤 적용한다.
3. Apps Script 편집기의 함수 목록에서 `setupDatabase`를 선택해 한 번 실행하고 권한을 승인한다.
4. 기존 프로젝트를 갱신하는 경우에도 `setupDatabase`를 다시 실행해 `RosterMembers`·`RecoveryCopies` 시트와 `WeekPlans.generatedJson` 열을 명시적으로 추가한다. 기존 행·시트는 삭제하지 않으며 일반 조회·로그인은 시트 구조를 자동 변경하지 않는다.
5. 함수 목록에서 `setupRecoveryMaintenance`를 한 번 실행해 제한된 Drive 권한과 매일 만료 정리 트리거를 승인한다. 이 검증에 실패하면 설치형 데이터 가져오기는 시작되지 않는다.
6. SSO 전환 전까지 함수 목록에서 `authorizeEmailLogin`을 한 번 실행해 메일 발송 권한을 승인한다. 이 함수는 메일을 보내지 않고 남은 일일 발송 한도만 확인한다.
7. 생성된 Google Sheets 파일을 확인한다. 학생에게 이 원본 Sheet를 공유하지 않는다.
8. `배포 → 새 배포 → 웹 앱`을 선택한다.
9. 실행 사용자는 배포 소유자, 접근 사용자는 Google 계정 보유자로 설정한다.
10. 배포 주소를 열어 마스터 화면이 표시되는지 확인한다.
11. 마스터가 학급과 담임 이메일을 등록하고, 담임이 학생 이메일 명렬을 등록한다.

매니페스트의 `webapp` 설정은 `access: ANYONE`, `executeAs: USER_DEPLOYING`이다. Google 로그인 사용자가 접속할 수 있지만 앱 데이터는 등록 이메일의 메일 인증을 마쳐야 읽을 수 있다. 중앙 Sheet는 배포자 권한으로만 읽는다. 라이브러리 문서 주소(`/macros/library/...`)가 아니라 배포 후 제공되는 웹 앱 주소(`/macros/s/.../exec`)를 사용한다.

기존 데이터베이스에 새 코드를 적용할 때는 먼저 소유자가 `setupDatabase`를 명시적으로 실행해야 누락된 시트가 추가된다. 읽기나 로그인 중 시트를 자동 생성·삭제하지 않으며, 이름이 `Sheet1`인 기존 시트도 보존한다. 기존 `Users` 시트의 머리글은 변경하지 않고 성별은 별도 `StudentProfiles`에 저장한다. 시험 배포를 먼저 사용하고 데이터가 올바른지 확인한 뒤 버전 배포를 갱신한다.

## 설치형 데이터 가져오기

1. Windows 설치형의 설정에서 `전체 백업 내려받기`를 눌러 `교실루틴_전체백업_날짜.json`을 만든다. 문서 데이터 폴더의 `교실루틴_설정.json`도 사용할 수 있다.
2. Apps Script 소유자가 `setupRecoveryMaintenance`를 완료했는지 확인한다. 가져오기 전 학급 데이터의 복구 JSON 사본을 Google Drive에 비공개로 만들며, 생성·읽기·권한 검증에 실패하면 가져오기를 중단한다. 사본은 생성 시각부터 30일 후 다음 정리 실행에서 영구 삭제하도록 설계했다. 실제 Google 계정에서 이 전체 주기를 아직 검증하지 않았다.
3. Apps Script 교사 화면의 `설치형 데이터 가져오기`에서 파일을 선택한다.
   `학생 명렬·이메일 연결`을 선택하면 이메일이 없어도 번호·이름을 `RosterMembers`에 저장한다. 이메일이 있는 학생만 `Users`에 로그인 계정이 연결된다. 아래 명렬 입력칸에 이메일을 추가해 같은 가져오기에서 연결하거나, 가져온 뒤 `명렬 등록·갱신`을 누를 수 있다.
4. 과목 안내, 주간 시간표, 아침·청소·하교 일정, 공통 안내·알림음, 크린토피아·우유 중 필요한 항목을 선택한다.
5. 알레르기 정보는 별도 체크한 경우에만 전송·갱신한다. 이메일 없는 학생의 정보도 명렬에 함께 저장된다.
6. 가져온 과목의 기본 링크는 비어 있을 수 있으므로 `과목 기본 안내·링크`에서 필요한 링크를 등록한다.
7. 종료 기록·전달 메모·자리 이력은 필요한 경우에만 선택한다. 자리 이력은 학생 번호·이름을 명렬에 연결하며 이메일은 필요하지 않다. 기존 이력을 덮어쓸 때 별도 확인을 받는다.
8. 온라인 데이터도 `온라인 전체 백업 내려받기`로 JSON 사본을 보관한다. 이 파일에는 학생 정보와 교사 전달 메모가 포함되므로 공유하지 않는다.

브라우저 보안상 Apps Script가 Windows의 로컬 데이터 폴더를 자동으로 읽을 수는 없다. 사용자가 파일을 선택했을 때만 브라우저가 읽는다. 선택하지 않은 항목과 API 키·설치형 비공개 메모는 전송하지 않는다. 수업 전달용 교사 메모는 명시적으로 선택했을 때만 비공개 시트로 가져온다.

가져온 항목은 하나의 중앙 Google 스프레드시트의 용도별 시트에 나뉜다. 구버전 백업의 학생에게 이메일이 없다면 학생 정보는 `RosterMembers`에 저장되고 `Users` 로그인 계정은 만들지 않는다. 수동 일정은 `RoutineSets`, 자동 일정은 `WeekPlans.generatedJson`에 주차별로 보관한다. 주간 시간표를 수정하면 해당 주의 가져온 자동 일정은 해제되고 변경된 시간표에서 다시 계산된다. 백업 JSON에는 학생 이메일과 알레르기 정보가 포함될 수 있으므로 개인 드라이브나 학교가 승인한 위치에만 보관한다. 한 번에 가져올 수 있는 최대량은 과목 40개, 주간 시간표 16주, 일정 합계 2000개(수동 일정 180개, 주차별 저장 크기 제한), 명렬 80명, 종료 기록·전달 메모 각 200건이다. 초과할 경우 잘라서 저장하지 않고 오류를 표시한다.

## 시간표와 학생 화면

- 교사는 주간 시간표에서 1~8교시, 학교급별 40·45·50분 기본 수업, 개별 수업 길이, 중간놀이, 점심시간, 5·6교시 하교 시각을 설정한다.
- 다음 주를 미리 열어 저장하거나 `지난 저장 주 복사`로 가장 가까운 이전 시간표를 가져올 수 있다.
- 학사관리 XLSX는 `주간 시간표 → 학사관리 XLSX 시간표 불러오기`에서 선택한다. 과목명이 기본 과목과 맞지 않으면 과목 설정을 먼저 추가한다. 파일 안의 날짜로 적용 주를 자동 결정하고, 이미 저장된 주라면 덮어쓰기 확인을 받는다.
- 오늘 일정의 수업을 누르면 과목 기본 안내와 링크가 수업 게시 양식에 채워진다. 실제 학생 화면 게시 여부는 교사가 다시 확인한다.
- 학생은 오늘 일정, 현재·다음 일정, 학급 공지, 오늘의 크린토피아·우유, 공용 타이머를 볼 수 있다.
- 시간표 저장은 진행 중인 `State`와 학생 응답의 `sessionId`를 변경하지 않는다.
- 웹앱 탭이 열려 있을 때 교사·학생 화면에 큰 일정 팝업을 띄운다. 소리를 내려면 각 기기에서 처음 한 번 `알림음 켜기·시험`을 눌러 브라우저 오디오 재생을 허용한다. 브라우저나 기기가 잠자기 상태인 동안에는 알림을 보장하지 않는다.
- 수업 종료 기록은 `RoutineRecords`에 남고, 종료 시각이 지난 일정은 기록 유무와 관계없이 화면에서 자동 종료로 표시된다. 학생용 전달 메모는 다음 수업 알림에 나타나며 교사 전용 메모는 학생에게 전달하지 않는다.

## 급식·날씨 설정

마스터가 학급 카드의 `교사 화면 열기`를 누르거나 담임이 로그인한 뒤 `급식·날씨 연결`에서 설정한다.

- 나이스: 학교 이름으로 검색해 교육청·학교 코드를 선택하거나 직접 입력한다. 공통 API 인증키 변경은 마스터 전용이다.
- 기상청: 동네예보 격자 X·Y를 입력한다. 공통 API 인증키 변경은 마스터 전용이다.
- 학생 명렬: `이메일, 번호, 이름, 성별, 알레르기번호` 순서이며 성별은 남·여, 여러 알레르기 번호는 `1|2|6`처럼 입력

알레르기 번호는 나이스 급식 표기의 1~19번을 사용한다. 학생 이름과 알레르기 정보는 나이스·기상청 API로 보내지 않으며, 가져온 식단과의 대조는 Apps Script 서버 내부에서 수행한다. 자동 결과는 참고용이므로 실제 배식 전 학교 식단표, 제품 표시와 학생별 관리 지침을 다시 확인해야 한다.

함수 목록에는 `setupDatabase`가 표시된다. 이 공개 진입점은 현재 접속 계정과 배포 소유자가 동일한지 확인한 후, 브라우저에서 직접 호출할 수 없는 내부 함수 `setupDatabase_`를 실행한다.

## 개인 계정 이메일 인증과 점검

이 구현은 개인 Google 계정이 앱과 비공개 중앙 Sheet를 소유한다. 학생이 입력한 이메일 문자열만 신뢰하지 않고, 등록된 주소로 보낸 6자리 인증번호를 확인한 뒤 임의 세션 토큰을 발급한다. 서버에는 토큰 원문 대신 해시만 저장하며 매 요청마다 만료·등록 상태·역할을 다시 확인한다.

교사는 학급 등록의 `담임 이메일`에 일반 Gmail을, 학생은 명렬 또는 백업에 학교 메일을 입력할 수 있다. 앱 소유자의 도메인을 학생에게 자동 강제하지 않는다. 필요하면 스크립트 속성 `CLASSROOM_HUB_STUDENT_DOMAINS`에 허용할 학생 도메인을 쉼표로 입력한다(예: `school.example.kr,students.example.kr`). 비어 있으면 교사가 등록한 모든 유효 이메일을 허용한다. 학교 메일이 Google Workspace 계정이어야 웹 앱의 Google 로그인 조건을 충족한다. 학교 관리자의 Apps Script 접속·메일 수신 정책에 따라 현장 확인이 필요하다.

인증 메일이 오지 않으면 다음을 점검한다.

- 학생 이메일이 교사 화면의 명렬에 정확히 등록돼 있는가
- 앱 소유자가 편집기에서 `authorizeEmailLogin`을 실행해 권한을 승인했는가
- 스팸함으로 이동하지 않았는가
- Apps Script의 일일 메일 수신자 한도를 넘지 않았는가
- 최신 버전으로 다시 배포했는가

이 방식은 메일 소유 확인이며 Google SSO 자체는 아니다. 학교 단위 통합 인증이 필요해지면 Google Identity Services의 ID 토큰을 별도 백엔드에서 검증하는 구조로 확장한다.

## 생성되는 시트

- `Users`: 이메일, 역할, 학급, 번호, 이름, 사용 상태
- `RosterMembers`: 이메일 연결 여부와 무관한 학생 명렬, 성별, 알레르기
- `StudentProfiles`: 학생 성별
- `Classes`: 학교, 학급, 담임 연결
- `State`: 학급별 현재 온라인 활동
- `Responses`: 학생별 준비·이해도·질문·마무리 응답
- `HelpQueue`: 도움 요청 대기열
- `AuditLog`: 주요 변경 기록
- `SubjectSettings`: 학급별 과목 기본 안내·링크
- `WeekPlans`: 주차별 시간표와 수업 시간 구조, 해당 주의 가져온 자동 일정, 충돌 감지용 버전
- `ClassAnnouncements`: 학생 공개 학급 공지
- `RoutineSets`: 설치형에서 가져온 수동 반복 일정
- `RoutineRecords`: 날짜별 수동 종료 기록
- `RoutineHandoffs`: 다음 수업 학생·교사 전달 메모
- `ClassPreferences`: 공통 안내와 알림음
- `DutyBoards`: 설치형에서 가져온 역할과 배정
- `SeatingBoards`: 현재 자리 배치와 옵션
- `SeatingHistory`: 확정된 자리 배치 회차
- `ClassControls`: 학급 공용 타이머 상태
- `LoginChallenges`: 인증번호 해시, 만료와 시도 횟수
- `AuthSessions`: 로그인 토큰 해시, 만료와 로그아웃 상태
- `RecoveryCopies`: 비공개 복구 사본의 작업 ID, 생성·만료 시각, 상태, 체크섬. 복구 본문은 이 시트가 아닌 앱 전용 Drive JSON 파일에 저장

## 개인정보 원칙

- 교사 전용 전달 메모는 `RoutineHandoffs`에 저장하고 교사 응답에만 포함한다. `State`나 학생 응답에는 넣지 않는다.
- 학생에게 반환하는 데이터에는 다른 학생 이메일과 응답 내용을 포함하지 않는다.
- 담임은 자신의 학급만, 학생은 본인의 학급만 접근한다.
- 원본 Sheet는 마스터와 운영 담당자에게만 공유한다.
- 설치형 데이터 가져오기 전 복구 사본은 해당 학급 범위로 만들고 인증번호·인증 세션·API 키는 포함하지 않는다. 30일 보관 후 매일 정리 작업에서 만료 사본을 영구 삭제한다. 정리 작업 실패 시 30일을 넘길 수 있으므로 운영자는 실행 기록을 확인해야 한다.
- 학교 개인정보 처리 기준이 개인 Google Drive 저장을 허용하는지는 운영자가 별도로 확인한다.

## 실시간 동작

학생의 버튼 응답은 즉시 저장한다. 담임 화면은 5초, 학생 화면은 12초 간격으로 상태를 갱신하고, 탭이 보이지 않을 때는 요청을 쉬게 한다. 남은 시간과 일정 알림은 서버 시각과 주간 시간표를 기준으로 각 기기에서 매초 계산한다.

Apps Script는 WebSocket 서버가 아니므로 닫힌 탭이나 잠든 기기에 강제 알림을 보낼 수 없다. 현재는 페이지가 열린 상태에서의 팝업·효과음을 구현했다. Windows 작업표시줄 알림은 대체 대상에서 제외했다.

## 2026-10-15 구현 상태와 배포 전 확인

- 명렬표 저장과 설치형 백업 가져오기는 다른 학급에 이미 등록된 학생 이메일을 관리자에게도 자동으로 이전하지 않는다. 학급 이동은 별도 명시적 절차가 필요하다.
- 전체 명렬 동기화에서 기존 학생을 비활성화할 때는 먼저 해당 학급의 복구 사본을 만들고 검증한다. 사본 준비가 실패하면 명렬 변경을 시작하지 않는다.
- `setupRecoveryMaintenance()`는 개인 정보가 없는 임시 파일로 Drive의 생성·비공개 권한·읽기·삭제를 시험한 뒤 매일 정리 트리거를 설치한다. 이 함수와 이후 실제 학급 복구 사본 생성은 아직 Google 계정에서 실행·검증하지 않았다.
- 30일 복구 사본은 생성 및 만료 정리 코드가 있지만, 사본 목록·복원 화면과 중간 실패 자동 복원은 아직 없다. 따라서 현재 로컬 코드만으로 백업 후 복구가 완성됐다고 간주하면 안 된다.
- Google SSO 전환은 실제 Apps Script HTMLService의 iframe 및 교사·학생 Google 계정으로 검증해야 한다. 그 전까지 기존 이메일 인증번호 경로를 비활성화하지 않는다.
- 위 검증 전에는 학생 실데이터가 연결된 공개 배포에 이 변경 사항을 올리지 않는다.
