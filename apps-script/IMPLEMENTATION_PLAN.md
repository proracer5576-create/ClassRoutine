# Apps Script 버전 안정화·설치형 대체 구현 계획

작성일: 2026-10-14
상태: 구현 전 검토안 — 이 문서는 코드·시트·배포를 변경하지 않는다.

## 1. 목표와 완료 정의

담임교사가 설치형 없이 Apps Script 웹 앱에서 하루 일과를 운영하고, 학생은 Chromebook·Android 탭에서 같은 학급의 공개 일정과 활동을 확인·응답할 수 있게 한다. Windows 작업표시줄 알림은 대체 범위에서 제외하고, **열려 있는 페이지의 큰 알림·효과음**으로 대체한다. 브라우저가 닫혔거나 백그라운드에서 실행이 제한될 때 알림을 보장한다고 표현하지 않는다.

완료는 기능이 화면에 있다는 뜻이 아니다. 권한 회수, 백업 복구, 설치형 데이터 호환, 실제 교사·학생 계정, 다수 기기, 좁은 화면, 배포 버전까지 모두 통과해야 한다. 일반 배포가 버전 6이고 최신 로컬 코드가 `@HEAD` 테스트 배포에 있는 현재 상태를 기준으로 한다. 버전 6의 URL과 데이터는 검증이 끝날 때까지 보존한다.

### 범위

- 변경 대상: `Code.gs`, `Client.html`, `Index.html`, `Styles.html`, `TimetableImport.html`, `appsscript.json`, Apps Script 테스트와 설명서.
- 설치형 코드와 설치본은 이 계획의 구현 범위가 아니다. 다만 설치형 JSON을 읽고 다시 설치형이 읽을 수 있는 JSON을 내보내는 호환성은 범위에 포함한다.
- 실사용 학생 이름·이메일·알레르기·메모를 개발용 저장소, 테스트 로그, GitHub에 넣지 않는다.
- `Code.js`는 `.claspignore`에 의해 배포되지 않는 오래된 별도 사본이다. 테스트가 `Code.gs`를 기준으로 돌아가도록 유지하고, 해당 사본의 삭제·보관은 구현 전에 파일 소유와 사용 여부를 확인한다.

## 2. 우선순위와 의존 관계

| 단계 | 목적 | 선행 조건 | 배포 게이트 |
|---|---|---|---|
| 0. 기준선·복구 준비 | 현재 코드·버전·시트 보존 | 없음 | 실데이터 변경 전 필수 |
| 1. 권한·스키마 안전성 | 이전 교사·전출 학생 접근 차단, 읽기 중 삭제 제거 | 0 | 통과 전 학생 계정 확대 금지 |
| 2. 가져오기 복구성 | 부분 반영 방지·복구 가능한 백업 가져오기 | 0, 1 | 통과 전 실제 전체 백업 반영 금지 |
| 3. 시간표 기능 일치 | 일정 예외·링크·시간 충돌·주차 저장 | 1, 2의 데이터 형식 확정 | 설치형 대체 판단 전 필수 |
| 4. UI·성능 | 제어 크기 통일, 화면 분리, 다수 접속 | 1~3 | 학생 기기 배포 전 필수 |
| 5. 통합 검증·배포 | 실제 계정·기기 검증과 버전 배포 | 0~4 | 일반 배포 갱신 |

단계 1~2의 안전성 문제는 기능 추가보다 우선한다. 각 단계는 테스트와 문서를 함께 갱신하고, 실패하면 다음 단계로 넘어가지 않는다.

## 3. 단계 0 — 기준선과 데이터 복구 준비

1. `clasp deployments`와 `clasp versions`로 일반 배포의 버전·설명·배포 ID를 기록한다. `clasp pull`은 로컬 변경을 덮을 수 있으므로 현재 작업 폴더에서 실행하지 않는다.
2. 중앙 Spreadsheet 전체의 **접근 제한된 사본**과 각 학급의 온라인 JSON 백업을 만든다. 백업 파일의 위치·소유자·생성 시각·복원 절차만 작업 기록에 남기고, 학생 정보가 포함된 파일이나 ID·키 값은 저장소에 기록하지 않는다.
3. 개발용 Apps Script 프로젝트와 테스트용 Spreadsheet를 실사용과 분리한다. 가명 학생·교사 계정과 가짜 알레르기·메모만 사용한다.
4. 버전 6 데이터와 새 코드의 읽기 호환성을 목록화한다. `Users`, `Classes`, `StudentProfiles`, `WeekPlans`, `SeatingHistory`의 기존 머리글·값이 새 스키마에서 보존되는지 확인한다.
5. 진행 중인 로컬 변경을 보존한다. 코드 편집 전 해당 파일의 변경 내용을 확인하고, 무관한 변경을 되돌리거나 강제로 `clasp push`하지 않는다.

완료 기준: 실제 시트의 복원 가능한 사본이 있고, 테스트 프로젝트가 별도이며, 일반 배포 버전 6으로 되돌리는 명령과 담당자가 문서화되어 있다. 코드 버전만 되돌려도 시트 데이터가 자동 복원되는 것은 아니므로 데이터 복구 절차도 별도로 검증한다.

## 4. 단계 1 — 권한·계정·스키마 안전성

### 4.1 담임 변경 시 권한 즉시 회수

- `Classes.teacherEmail`을 단일 담임의 현재 권한 원본으로 정한다. 교사 요청마다 `Users.role/classId/active`와 현재 `Classes.teacherEmail`을 함께 확인한다. 마스터는 별도 경로로 판정한다.
- `saveClass()`에서 기존 담임과 새 담임을 비교하고, 변경 시 같은 잠금 구간에서 기존 교사 계정을 비활성화하거나 다른 담당 학급이 있으면 명시적 멤버십으로 이전한다. 현재 데이터 모델은 계정당 학급 하나이므로 첫 구현은 **한 담임·한 학급**을 기준으로 한다.
- 기존 담임의 `AuthSessions`를 폐기한다. Google 활성 이메일로 자동 식별되는 경우에도 현재 담임 관계 검사에서 거절되도록 한다.
- 마스터 화면에 ‘담임 변경’과 변경 전·후 이메일, 권한 회수 안내를 별도 작업으로 제공한다. 현재의 ‘학급 연결하기’ 버튼과 혼동하지 않게 한다.
- 회귀 시험: 변경 전 교사는 읽기·쓰기·백업 가능, 변경 직후 같은 토큰과 Google 세션 모두 거절, 새 교사는 접근 가능, 마스터는 유지.

### 4.2 명렬 변경과 학생 비활성화

- ‘학생 추가·수정’과 ‘전체 명렬 동기화’를 구분한다. 전체 동기화 전에 신규·변경·비활성화될 이메일을 미리 보여 주고 확인받는다. 빈 명렬은 전체 비활성화 확인 없이는 적용하지 않는다.
- 명렬에서 빠진 학생은 행을 지우지 않고 `Users.active=false`로 바꾸며 기존 인증 세션을 폐기한다. 기록 보존·삭제 기간은 학교 개인정보 처리 기준을 확인한 뒤 확정한다.
- 이메일 변경은 기존 계정의 접근 폐기와 새 계정 등록을 한 작업으로 처리한다. 번호·이름만 같은 학생을 자동으로 같은 사람이라고 단정하지 않는다.
- 회귀 시험: 전출 학생의 기존 토큰·새 로그인 모두 거절, 재등록 시 명시적으로 활성화, 다른 학급 학생을 담임이 빼앗을 수 없음.

### 4.3 로그인 응답과 요청 제한

- 등록·미등록 이메일의 `requestLoginCode()` 응답 모양과 문구를 동일하게 한다. 미등록 주소에도 검증에 사용할 수 없는 불투명 요청 ID를 반환해 등록 여부를 노출하지 않는다.
- 등록 여부와 관계없이 사용자 임시 키·이메일별 요청 제한을 적용한다. 인증 코드는 일회용·유효기간·시도 횟수 제한을 유지하고, 메일 발송 실패 시 사용 불가능한 도전 과제를 정리한다.
- 학교 메일과 일반 Gmail 사용은 허용하되, 이메일 도메인만으로 교사·학생 역할을 추정하지 않는다. `Users.role`과 현재 학급 관계가 최종 권한을 결정한다.

### 4.4 읽기 경로에서 자동 삭제·수정 금지

- `getDb_()`와 일반 조회/로그인에서 `ensureSchema_()`가 시트를 생성하거나 `Sheet1/시트1`을 삭제하지 않도록 분리한다. 초기 설치·스키마 갱신은 마스터가 편집기에서 실행하는 명시적 작업으로 만든다.
- 스키마 갱신은 앱 소유 시트의 머리글만 추가하고, 모르는 시트는 이름이 `Sheet1`이어도 보존한다. 필요한 마이그레이션은 현재 스키마 버전과 적용 이력을 기록하고 재실행해도 중복되지 않게 한다.
- 회귀 시험: 데이터가 들어 있는 `Sheet1`을 둔 채 학생·교사·마스터 로그인/조회/저장을 실행해도 그 시트가 변하지 않음.

### 4.5 전역 API 키와 학급 설정 분리

- 공통 NEIS/KMA API 키 수정은 마스터만 허용한다. 담임은 자기 학급의 학교·교육청 코드와 기상 격자만 수정한다. 화면과 서버 함수를 분리해 학급 권한 검사만으로 전역 키에 접근하지 못하게 한다.
- `saveClass()`가 기존 `Classes` 행을 병합한 뒤 이름·담임 관련 필드만 변경하게 하여 학교 코드·격자·생성 시각을 보존한다.
- 회귀 시험: 한 담임의 수정이 다른 학급 연동에 영향 없음, 학급 이름/담임 변경 후 기존 연동값 동일.

## 5. 단계 2 — 백업 가져오기와 복구 설계

`LockService`는 동시에 실행되는 코드를 직렬화하지만 시트 여러 곳의 쓰기를 한꺼번에 되돌리는 트랜잭션은 아니다. 따라서 ‘검증 → 복구 지점 생성 → 적용 → 검증 → 완료’ 작업으로 만든다.

### 5.1 미리보기와 서버 측 전체 검증

- 선택된 항목만 서버로 보낸다. 서버는 버전, 크기, 날짜, 모든 학생 이메일, 과목 참조, 주간 시간표, 반복 일정, 역할 배정, 자리 배치, 인계 메모를 **쓰기 전에 모두** 검증한다.
- 기존 데이터와 비교해 ‘새로 추가/변경/유지/대체/비활성화’ 건수를 돌려준다. 0건짜리 백업으로 기존 일정·역할을 비우거나 기존 시간표·자리를 덮을 때는 항목별 확인을 요구한다.
- 800KB·기록 200건 제한에 걸리는 백업은 조용히 일부만 가져오지 않는다. 분할 전송은 작업 ID와 순서·체크섬을 가진 멱등 청크로 설계하고, 첫 릴리스에서 구현하지 못하면 화면에 제한과 분리 절차를 명시한다.

### 5.2 복구 지점과 작업 일지

- 적용 직전, 변경 대상 학급의 기존 행을 `ImportJobs`와 `ImportBackupChunks` 같은 앱 전용 시트에 3만 자 이하 조각으로 보관한다. 조각 수·전체 체크섬을 확인하기 전에는 원본 행을 건드리지 않는다. API 키 등 가져오기 대상이 아닌 값은 복구 사본에도 불필요하게 중복하지 않는다.
- 작업 상태는 `PREPARED → APPLYING → COMPLETE`로 기록한다. 실패 시 `RECOVERY_REQUIRED`가 되고 해당 학급의 후속 가져오기·관련 쓰기를 막는다. 자동 복구를 시도하되, 복구 자체가 실패해도 관리자가 같은 지점에서 재시도할 수 있게 한다.
- 복구 지점의 보존 기간·접근권한·폐기 방식은 학교 정책과 함께 확정한다. 시트 안에 보관하는 사본도 학생 개인정보이므로 일반 사용자에게 원본 Spreadsheet를 공유하지 않는다.
- 장애 주입 시험: 각 섹션의 첫 행/중간 행/마지막 행에서 인위적으로 실패시켜, 복구 뒤 기존 데이터와 체크섬이 같고 중복 행이 없음을 검증한다.

### 5.3 자리 이력은 활성 세대로 전환

- 기존 `SeatingHistory`를 먼저 삭제하지 않는다. 새 이력을 작업 ID가 포함된 별도 세대로 모두 기록한 뒤 `SeatingBoards`의 활성 이력 세대만 전환한다. 세대 정보가 없는 기존 자료는 레거시 세대로 읽는다.
- 새 세대 저장 또는 전환이 실패하면 기존 활성 세대를 계속 사용한다. 이전 세대 정리는 복구 확인과 보존 기간이 지난 뒤 별도 작업으로 한다.

### 5.4 왕복 호환

- 설치형 전체 백업 JSON → 온라인 가져오기 → 온라인 전체 백업 JSON → 설치형 복원 시험을 가명 자료로 수행한다.
- 과목·링크·주차·예외시간·일정·공통 메시지·명렬 이메일·성별·알레르기·역할·자리·종료 기록·학생/교사 전달 메모를 필드별로 비교한다. 온라인 전용 데이터는 별도 필드로 명시하고 설치형이 모르는 필드를 안전하게 무시하는지 확인한다.
- 실제 백업을 적용할 때는 먼저 복원 가능한 원본 백업을 별도로 보관하고, 결과 요약을 사용자에게 보여 준다.

## 6. 단계 3 — 일정과 설치형 기능 차이 해소

### 6.1 주간 시간표의 예외시간

- 현재 `timetable[요일][교시] = 과목ID` 형식은 유지해 기존 주차를 읽는다. `WeekPlans.planJson`에 선택 사항 `periodOverrides[요일][교시]`를 추가한다. 예외 필드는 수업 시작 시각, 수업 길이, 뒤따르는 쉬는 시간, 사전 알림, 별도 안내와 자료 링크다.
- 과목 기본값 → 해당 교시 예외값 → 개별 일정 별도값 순으로 우선순위를 명시한다. 빈 교시는 숨기고, 이후 교시 시각은 앞선 예외를 반영해 다시 계산한다. 고정 시작 시각과 앞 일정이 충돌하면 저장 전에 경고한다.
- 학교급을 바꾸면 공통 기본시간만 변경하고 개별 예외는 유지한다. 1~8교시, 5·6교시 하교 정시 알림, 점심 위치·중간놀이 설정을 회귀 시험한다.

### 6.2 중간놀이·점심 동시 설정

- 같은 교시 뒤에 둘 다 켜면 현재처럼 점심을 버리지 않는다. 권장 동작은 **중간놀이 다음 점심을 순서대로 배치**하고, 저장 화면에서 두 구간을 모두 미리 보여 주는 것이다. 학교 운영상 허용하지 않을 선택이라면 사용자 확인 후 입력 단계에서 금지할 수 있다.
- 테스트는 같은 위치, 서로 다른 위치, 마지막 교시 뒤, 3·4·5교시 점심, 쉬는 시간 0분을 포함한다.

### 6.3 링크·메시지·알림

- 개별 일정에 `resourceLabel/resourceUrl`을 저장·표시한다. 개별 일정 링크가 없을 때만 과목 기본 링크를 사용한다. 학생 공개 메시지와 교사 전용 메모의 경계를 유지한다.
- 주간 교시와 개별 일정 모두 사전 알림 분 수를 조정하거나 끌 수 있게 한다. 하교는 사전 알림 없이 정시에만 알린다. 알림에는 현재 시각·시작 시각·남은 시간을 크게 표시한다.
- 페이지 내부 큰 알림은 확인 시 소리를 즉시 멈추고, 이미 본 알림 키는 날짜·학급·일정·단계로 관리한다. 페이지가 닫혀 있던 동안의 알림은 소급 반복하지 않는 정책을 명시한다.

### 6.4 지난주 복사와 동시 수정

- 이전 주 복사는 대상으로 보이는 주의 `revision`과 원본 주차·revision을 함께 전송한다. 잠금 안에서 둘 다 재확인하고, 대상이 달라졌으면 덮어쓰지 않는다.
- 교사·마스터 두 화면에서 같은 주를 수정하는 시험과 XLSX 가져오기 직후 복사 시험을 추가한다.

## 7. 단계 4 — 화면·정보 구조·성능

### 7.1 UI 통일

- 기존 ‘햇살 학급 게시판’ 색·서체·현재 일정 중심의 정보 위계와 사용자가 익숙한 일정 편집 방식을 유지한다.
- 같은 수준의 주요 버튼은 최소 높이 44px, 본문 버튼 글꼴 13~14px의 공통 토큰을 쓴다. 로그아웃·학급 열기·학생 응답 등 화면마다 달라진 9~11px 버튼을 재검토하고, 상태·비활성·키보드 초점도 맞춘다.
- 교사용 상단은 ‘지금 운영’과 ‘설정·가져오기’를 구분한다. 시간표·과목·일정·명렬·외부 연동을 접이식 설정 영역 또는 탭으로 묶되, 현재 입력한 초안이 주기적 새로고침으로 사라지지 않게 한다.
- 각 카드의 반복적인 영문 소제목은 꼭 필요한 곳만 남기고 일정명·현재 시각·남은 시간이 가장 먼저 보이게 한다.
- 320/375/414/768px와 교실 대형 화면에서 제목·버튼·알림이 잘리지 않는지 확인한다. `overflow-x:hidden`으로 넘친 내용을 가리는 방식에 의존하지 않는다.

### 7.2 다수 기기와 접근성

- 현재 교사 5초, 학생 12초 조회가 만드는 시트 읽기·외부 API 호출 횟수를 측정한다. 학급 공통 데이터는 한 번 읽어 재사용하고, 학생별 데이터만 필요한 범위에서 조회한다. 화면이 보이지 않을 때는 조회를 줄이고, 활동 중에는 필요한 지연 기준에 맞춰 조정한다.
- 실제와 분리한 계정으로 교사 1명·학생 24명 동시 접속, 로그인·응답·도움 요청·타이머·알림 시나리오를 수행한다. 지연, 오류율, 메일 발송 잔여량, Apps Script 실행 기록을 남기고 임계치가 넘으면 폴링 간격 또는 데이터 구조를 조정한다.
- `dialog`와 큰 알림의 키보드 이동·초점 복귀·스크린리더 문구·움직임 줄이기·음소거 상태를 확인한다. Chromebook과 Android Chrome에서 음향은 사용자의 첫 조작 후에만 보장한다.

## 8. 단계 5 — 테스트·문서·배포

### 자동 시험

- 현재의 정규식 기반 계약 시험은 유지하되 서버 함수에 `SpreadsheetApp`, `PropertiesService`, `Session`, `MailApp`, `LockService` 모형을 주입하는 행동 시험을 추가한다.
- 필수 회귀: 이전 담임/전출 학생 권한 회수, 미등록 이메일 응답 동일성, `Sheet1` 보존, 전역 키 권한, 학급 수정 시 연동 보존, 가져오기 실패·복구, 같은 위치 중간놀이/점심, 주차 충돌, 일정별 링크, 설치형 백업 왕복.
- UI는 Google 호출을 모사한 화면 시험과 실제 `@HEAD` 시험을 구분한다. 자동 테스트 30개 통과만으로 실제 Google 배포 통과라고 판단하지 않는다.

### 실제 수락 시험

1. 테스트 마스터·담임·학생 계정으로 각 화면과 권한 거부를 확인한다.
2. 가명 학급에서 시간표 2주, 개별 일정, 과목 링크, 급식·날씨, 1인 1역, 자리 배치, 수업 응답을 하루 흐름대로 실행한다.
3. 설치형 백업을 가져온 뒤 온라인 백업을 내보내고 재복원해 항목 수·핵심 필드·학생별 비공개 경계를 비교한다.
4. 수업 중 교사 1명·학생 24명 접속을 시험한다. 실제 학생에게 배포하기 전에는 가명 계정으로 한다.
5. 오류를 주입해 복구 버튼과 버전 6 롤백 절차를 실제로 연습한다.

### 배포 순서

1. 코드·테스트 통과와 실데이터 백업 확인 후 `clasp push`로 `@HEAD`만 갱신한다. 이 단계는 일반 배포를 바꾸지 않는다.
2. `@HEAD`에서 실제 계정·시트·기기 시험을 완료한다. 학급 데이터를 쓰는 시험은 분리된 테스트 시트에서 먼저 수행한다.
3. 사용자 승인 후 불변 버전을 만들고 **기존 일반 배포 ID**를 새 버전으로 갱신한다. URL을 바꾸지 않는 것을 기본으로 하며, 변경 전 버전 번호를 기록한다.
4. 마스터·담임·학생 순서로 제한된 파일럿을 진행하고 이상 없을 때 전체 학급으로 확대한다.
5. 장애가 나면 일반 배포를 이전 버전으로 되돌리고, 시트 변경은 단계 0 사본/단계 2 복구 지점으로 별도 복구한다. 구조 변경은 이전 코드도 읽을 수 있는 추가형으로 설계한다.

## 9. 최종 합격 기준

- 이전 담임과 비활성 학생은 인증 방식·기존 토큰과 관계없이 해당 학급을 읽거나 수정할 수 없다.
- 로그인·조회만으로 기존 사용자 시트가 생성·삭제·변경되지 않는다.
- 백업 가져오기 중 어느 단계에서 실패해도 이전 데이터를 그대로 유지하거나 기록된 복구 지점으로 **검증 가능한 복원**을 완료한다. 복구 전에는 정상 완료로 표시하지 않는다.
- 같은 교시 뒤 중간놀이·점심이 모두 있을 때 둘 다 표시되고 뒤 수업 시각이 정확하다.
- 주차별 저장·지난주 복사·다른 화면의 동시 수정·설치형 JSON 왕복이 통과한다.
- 교사 전용 메모·다른 학생의 알레르기/응답은 학생 응답에 포함되지 않는다.
- 같은 등급의 버튼 크기와 글꼴이 일치하고, 320px부터 대형 화면까지 가로 잘림 없이 핵심 일정과 알림이 읽힌다.
- 교사 1명·학생 24명 실기기/실계정에 준하는 접속 시험이 통과하고, 실제 Google 실행 로그에서 실패 원인을 확인할 수 있다.
- README·설명서·대체 검증표·배포 버전 정보가 실제 동작과 일치한다.

## 10. 구현 전에 확정할 운영 선택

1. **담임 관계:** 우선 한 담임·한 학급을 권장한다. 공동담임이나 교사의 복수 학급 담당이 필요하면 `Users.classId` 하나로 확장하지 말고 별도 멤버십 설계를 먼저 확정한다.
2. **명렬 저장:** ‘추가·갱신’과 ‘전체 동기화’를 별도 버튼으로 두고, 전체 동기화에서 빠진 학생을 확인 후 비활성화하는 안을 권장한다.
3. **API 키 소유:** 개인 계정으로 운영하는 마스터가 공통 키를 관리하고 담임은 학급 코드만 수정하는 안을 권장한다.
4. **같은 교시의 두 휴식:** 중간놀이 다음 점심을 연속 배치하는 안을 권장한다.
5. **백업 복구 사본 보존:** 보존 기간과 삭제 담당자는 학교의 개인정보 처리 기준에 맞춰 사용자와 확정한다.

위 선택이 확정되면 단계 0→5 순서로 구현한다. 단계 1~2가 끝나기 전에는 최신 코드를 일반 배포로 교체하지 않는다.

## 11. 2026-10-14 확정된 운영 결정 및 구현 상태

- 학급당 담임은 1명이다. 담임 교체 시 이전 담임 계정과 기존 인증 세션을 비활성화하고, 요청마다 현재 `Classes.teacherEmail`과 일치하는지 재검사한다.
- 로그인은 Google 계정 SSO로 전환한다. 교사는 개인 Gmail, 학생은 학교 계정을 사용할 수 있어야 한다. 현재 이메일 인증번호 로그인은 SSO 전환 검증이 끝날 때까지 기존 공개 배포에서 유지한다.
- 명렬은 `등록·갱신`과 `전체 동기화`를 분리한다. 전체 동기화에서 빠진 학생은 로그인과 기존 세션만 비활성화하고 활동·기록은 삭제하지 않는다.
- 가져오기나 구조 변경 직전에 복구 사본을 만든다. 사본은 비공개로 30일 보관하고 만료 후 삭제한다. 자동 삭제가 실제로 동작하는지 실계정 검증 전에는 보관 기간을 보장한다고 표시하지 않는다.
- 공통 NEIS/KMA API 인증키는 마스터만 수정한다. 중간놀이와 점심이 같은 교시 뒤에 있으면 중간놀이 다음 점심 순서로 배치한다.

첫 로컬 구현에서 담임 교체 권한 차단, 명렬 전체 동기화와 제외 학생 비활성화, 마스터 전용 API 키 변경, 일반 조회 시 스키마 자동 변경 금지, 중간놀이·점심 동일 위치 처리, 가져오기 전 학급 범위 비공개 JSON 사본과 30일 만료 정리 코드를 반영했다. 복구 사본은 전체 Sheet 복사 대신 앱 전용 Drive 파일로 만들어 `drive.file` 권한만 사용한다. 실계정의 권한·생성·읽기·만료 삭제, 복원 절차와 중간 실패 복구는 아직 검증되지 않았다. SSO, 실제 Google 계정·기기 검증, 일반 배포 갱신도 완료되지 않았다.
